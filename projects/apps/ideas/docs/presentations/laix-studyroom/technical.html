Open with the boundary, not a feature list. LAIX is not a model, memory store or agent framework. It is the decision layer. Core is the substance; app kit is how an app uses it; the host owns the world.
Three boundariesWho imports what

The architecture rule

Core. App kit. Host.

Core

Contracts, request/decision shapes, action and attention policies, eight packs, outcome learning, evaluation, perception, resources.

imports only core
App kit

Layer, runtime, execution, records, delivery, platform, live-context loop, bench.

imports core · optional · frozen
Host

Memory, ingestion, connectors, orchestration, permissions, missions, app policy, UI. Includes host services such as PPMA, Digital Mate and JiuwenSwarm.

imports LAIX · LAIX never imports host

Core is the base. A host can call core directly, or add the app kit for records, execution and delivery.

Path A: host → core. Path B: host → app kit → core.

PPMA is a host service. It owns memory, consent and audit; the host passes only authorized generic context to LAIX. LAIX never calls PPMA.

Boundaries · core / app kit / host02
This is the slide builders remember. Core has no host knowledge. App kit is optional and frozen. The host owns the product. If a host name leaks into LAIX, the boundary is broken.

App kit · integration surface05

The requestTwo shapes, one decision

How Layer chooses a policy

Attention or action. Same output.

Attention request

signals — deadline, risk, opportunity
context — now, quiet hours, severity
policy — built-in attention
verb — usually guide, wait or observe

Action request

situation — beliefs, goals, constraints
options — benefit, risk, delay, cost
policy — built-in action or custom
verb — wait, guide, ask, act, verify, escalate

A custom policy reads DecisionRequest.attributes. The ten decision classes all return the same public Decision.

Request · attention / action06
Two request shapes explain policy selection. Attention is signals plus context. Action is situation plus options. A custom policy uses attributes. All ten classes return the same decision shape, which is what makes the host integration stable.

The contractWhat a decision carries

One shape for every policy

Not just a verb.

GroupFields
Answerverb, action_id, reason_code, rationale
Confidenceconfidence, confidence_source, calibrated
Rankingscore, breakdown, cost_of_waiting
Choicealternatives, constraints_applied, requires_approval
Supportevidence, escalation, intent

The host sends a DecisionRequest; LAIX returns this Decision. A score ranks inside one policy. Confidence is not a probability unless calibrated says so.

Contract · decision shape08
This is the builder contract. A score is not a probability. The decision carries alternatives and constraints, which is why the host can explain it. The audit fields are what make the record reproducible.
PoliciesRules, packs and the registry

One active policy at a time

The domain rules live in the host.

Built in

Attention and action. Layer selects them from the request shape.

Packaged

Active perception, safety, replanning, allocation, negotiation, preference, verification, escalation.

Custom

Your policy class with a name, a version and a decide(request) method.

layer = Layer(policy=LearningPolicy()) layer.register_policy("safety", SafetyConstrainedPolicy()) layer.use_policy("safety")

A policy returns the same decision shape. Add a bench case before changing behaviour.

Policies · built in / packaged / custom09
A custom policy is expected, not a workaround. LAIX owns the decision shape and mechanics; the host owns domain rules. The registry lets one layer expose several policy packs without changing the host contract.

Integration · StudyRoom10
Be precise about what StudyRoom uses. It uses the core contracts, Layer, a custom policy and records/outcomes. It does not use Live Context, Platform or outcome learning. That is fine for Phase 0, but do not claim the whole package is exercised.
Live ContextPerception under a budget

Cheap always. Deep when it pays.

The host supplies detectors. LAIX decides what runs.

EventSubject, time, raw context.
Cheap detectorAlways runs. Low cost.
BudgetUncertainty, gain, cost, latency.
Deep detectorOnly when it clears the threshold.
FrameWhat ran, what was skipped, what was found.
frame = context.perceive(event, uncertainty=0.8) # frame: detections, allowed, skipped, remaining uncertainty, cost

A natural StudyRoom extension: camera hand raise or speech as a cheap detector; a deeper model only when uncertainty is high.

Live Context · cheap vs deep11
Live Context is the perception loop, not the decision. The host owns detectors and events. LAIX decides which detectors run under uncertainty and budget, and returns a frame that records what was skipped. This is the path to real multimodal StudyRoom.

Extension pointsHow to add without forking

The package is meant to be extended at the edges

Replace a piece, not the layer.

NeedUse
New decision rulesA policy with name, version and decide(request).
New perceptionA detector with detect(event); cheap or deep.
New executionExecutionBridge or a Platform.
New storageImplement StateStore or OutcomeStore.
New channelImplement DeliveryPort.

Integration checklist: pin the tag, connect one host path, choose or write one policy, record decisions and outcomes, run the bench, shadow before switching.

This is the practical close for builders. Do not fork LAIX. Replace a policy, detector, execution integration, store or delivery port. The integration checklist is the first week of work.
